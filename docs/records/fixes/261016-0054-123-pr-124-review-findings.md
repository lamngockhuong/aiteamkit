# Fix: a job can run code as the coordinator through its worktree's .git file, and 36 gaps the review of PR #124 found

## In short

The review of pull request #124 found one blocking hole in `atk:orchestrate`. A job may write only
inside its worktree, and the worktree's `.git` file sits there. A job that rewrites it to point at a
git directory of its own, with `core.fsmonitor` set, gets that script run with the coordinator's
rights the next time the coordinator runs `git status` in the worktree. The text compared the file
only after running those commands. The fix makes reading that file as plain text the first act after
a job ends. Every later git command in the worktree is pinned to the recorded git directory, and a
changed `.git` file fails the job and is never accepted on anyone's word.

The same review raised 36 `SHOULD FIX` findings, cases the new baseline, the waits and the probe
left undefined. Each is now written into the reference that owns it. Lam Ngoc Khuong set the scope
on 2026-10-16: `B1` and all 36 in this pull request, the 26 `NIT`s to a follow-up issue. They made
two decisions the same day. They widened #123 `S17`: a job commit is asked about before any hook or
clean filter fires, not only a pre-commit hook. And they restored the wait for an input that was
edited but not committed (`S19`). Two review rounds then closed everything they reopened, apart from
six `SHOULD FIX` findings of the second round. Those were fixed after it, so no review has read
their fixes yet. Lam Ngoc Khuong approves this report.

### B1. A job can get its own script run with the coordinator's rights through the worktree's `.git` file

- **Cause.** `plugins/atk/skills/orchestrate/references/worktrees.md:108-126` on `eb47c4f`. After a
  job ends, the text ran `git -C <worktree> rev-parse HEAD`, `rev-parse --git-path index.lock` and
  `git status` in the worktree. Only then did it compare the `gitdir:` line, which the job could
  have rewritten.
- **Evidence.** A reproduction in a scratch repository. A worktree's `.git` was rewritten to
  `gitdir: ./x`, with `x` a git directory whose `config` sets `core.fsmonitor` to a script inside the
  worktree. Output:

  ```
  ['rev-parse', 'HEAD'] rc 128 no run HEAD
  ['rev-parse', '--git-path', 'index.lock'] rc 0 no run /tmp/.../b1/wt/x/index.lock
  ['status', '--porcelain'] rc 0 fsmonitor ran ?? h.sh
  ```

  `git status` ran the job's script, and `--git-path` resolved into the planted directory. The same
  `git status` with `--git-dir` set to the recorded line ran nothing. The new check in `CLAUDE.md`
  asserts both.

## 5. The change

All 37 findings are prose fixes in the files that own each rule; no script changed.

- **`worktrees.md`** carries most of them. It gains a section, Before git runs in a worktree: a
  guard that reads each worktree's `.git` file, its `commondir` and the configuration and hooks git
  loads, as plain files hashed outside any repository, before any `git` command there. That covers
  a job that ended, a worktree a previous run left, and each skill the coordinator runs in a
  worktree.
  - A changed `.git` or `commondir` is never accepted on anyone's word.
  - A changed configuration file or hook is shown before the person is asked about it.
  - The coordinator's own commands are pinned with `--git-dir` and `GIT_COMMON_DIR`.
  - The baseline names what it holds, how it is hashed, and when it is re-recorded: only the
    coordinator's own paths after a file write, and compared before and after a commit, a review
    or a verify run.
  - Step 1 now covers the run directory, refs, absent files and nested repositories. Step 3 asks
    before any hook `git add` or `git commit` fires and any `clean` or `process` filter driver. The
    waits, the bases a piece starts from, inputs a commit has not caught up with, and a review
    report's name are each written once.
- **`ways-to-run.md`** changes the probe. It is checked on disk, its pane is recorded and stopped,
  another provider's CLI waits for the PM's yes, a refused session refuses the run, and a probe
  that fails after the yes changes no way unasked. The resume offer is relayed and never
  pre-answered, a subagent job has no timeout, and a timed-out agent is stopped before its job is
  recorded `failed`.
- **`proposal.md`** adds the chain states `needs-person` and `parked`. A parked question is stored
  masked and its agent is stopped at once. Who is in the session is asked once. Every wait now has
  one exit rule, and the cost names what runs with the coordinator's rights.
- **`SKILL.md`** of orchestrate records each piece's base and reviews against it, never against
  `(detached)`. Its step 3 cites the wait rule. It stays at 299 lines.
- **Shared files and `atk:review`.**
  - `host-capabilities.md` states the commit rule as the reference now has it.
  - `secret-scan.md` rewrites a two-dot range target to three dots.
  - `atk:review` names a range report after its two ends, and `report-format.md` says each target
    kind carries its own identifiers. `artifact-paths.md` and both overviews point there rather
    than restate it.
- **Docs.** Both `codebase-summary.md` rows are current.
- **`CLAUDE.md`** gains a check of the git behaviour the text rests on. It asserts the ignored and
  nested listing lines, `--no-filters`, and that a rewritten `.git` or `commondir` reaches a planted
  fsmonitor unless both pins are set.

**Tidy.** `/simplify` ran as four read-only agents. Applied:
- the hook list cited rather than repeated, and stated as every hook rather than four;
- the review naming rule given one owner;
- the `.git` read once per pass, and the common directory hashed in one call;
- three wording repairs.

Skipped, each because it would change behaviour or add machinery:
- skipping step 1 before a commit when the same pass already ran it;
- caching the overlap diffs;
- moving the two-dot rule into review's `SKILL.md`, which is at 299 lines;
- `git -c` in the check.

The reproduction was re-run afterwards.

**Reference documents.** No public contract changed. `atk:review`'s report name is defined in its
`SKILL.md`, which this change edits.
