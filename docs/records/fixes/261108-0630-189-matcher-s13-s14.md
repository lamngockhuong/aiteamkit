# Fix: findings matcher S13 and S14

## In short

The benchmark reads a review report and credits each planted defect the report finds. Two report
shapes were misread. A findings heading that counts what was refuted, `## Findings (3 confirmed, 1
refuted)`, and a finding titled `Finding 1: The token check is dropped ...` were both taken for a
section of set-aside findings, so the defects under them were not credited (S13). A numbered heading
`## 4. Open questions for Bench PM` under a findings heading was taken for a finding's title, so a
question in it credited a defect (S14). The set-aside words now count only right after the plural
"findings", or after `were`, `that were`, `considered and` or `verified and`, and a section name
opening a heading is recognised after its number too. The change is to the benchmark's test code
only, two review rounds found nothing blocking, and Lam Ngoc Khuong, as Tech Lead, approves it and
answers the two open questions the review left.

## After the last round

The second round fixed nothing, so there was nothing for a closing read to cover. Its report is
`docs/derived/reviews/tests-bench-matcher-261108-0627.md`: 0 `BLOCKING`, 0 `SHOULD FIX`, 5 `NIT`.

## 1. Symptom as captured

From issue #189, raised by the closing read of the review loop of #188:

> **S13 (regression from #188's S11 fix).** `FINDINGS_SET_ASIDE` in `tests/bench/lib/checks.mjs`
> matches "ruled out", "dropped", "refuted" or "rejected" anywhere after "Finding". So `### Finding
> 1: The token check is dropped when ADMIN_TOKEN is unset` under `## Findings` is read as a section
> set aside and D1 is lost, and `## Findings (4 confirmed, 1 refuted)` shuts out every finding under
> it.
>
> **S14.** A numbered section heading with extra words under a heading that opens with "Findings",
> `## 4. Open questions for Bench PM`, is still read: `TITLED` matches the `4` before
> `SECTION_OPENS` is tried, so a question in it credits D2.

Environment: Node, `node tests/bench/check-matcher.mjs` on `main` at `c1042f7`, no model call.

## 2. Root cause

Two mechanisms in `findingsIn` of `tests/bench/lib/checks.mjs`.

- **S13.** `FINDINGS_SET_ASIDE` was
  `/^(?:\d+[.)]?\s*)?findings?\b.*\b(?:ruled out|dropped|refuted|rejected)\b/i`: the `.*` let the
  set-aside word stand anywhere after a singular or plural "finding", so a count in a findings
  heading or a word in a finding's title closed the section (`tests/bench/lib/checks.mjs:556` before
  the fix).
- **S14.** `modeOf` tested `TITLED`, which matches a heading opening with a number, before
  `SECTION_OPENS`, so a numbered heading that opens with a section name and goes on returned `null`
  and inherited the findings mode of its parent (`tests/bench/lib/checks.mjs:571-572` before the
  fix). A numbered section name with nothing after it was already caught, by `SECTION_ALONE`.

Hypotheses: two, both proved, none ruled out.

## 4b. Recorded intent, and the conflict when there is one

Spec: issue #189 itself, written by the maintainer, which names both shapes and the direction of each

`node tests/bench/check-matcher.mjs` green. The intent the matcher already records holds: the case

one of the names `SECTION_OPENS` carries. No record contradicts the change.

## 5. The change

In `tests/bench/lib/checks.mjs`, `FINDINGS_SET_ASIDE` now reads
`^(?:\d+[.)]?\s*)?findings\s+(?:that were\s+|were\s+|considered and\s+|verified and\s+)?(?:ruled out|dropped|refuted|rejected|set aside)\b`,
so the set-aside word has to follow the plural "findings" directly or through one of four
qualifiers; `SECTION_OPENS` accepts the same optional leading number as its neighbours; and `modeOf`
tests `SECTION_OPENS` before `TITLED`, leaving `SECTION_ANYWHERE` and the bare `dropped` after it.
The comments above them say the same. Two cases were added to `tests/bench/matcher-cases/` and to
`expected.json`. This is the smallest change that removes both causes: one pattern narrowed, one
pattern given the prefix the others already carry, and one check moved.

Tidy step: `/simplify` ran four agents on the lines the fix touched. It replaced the first form of the
S14 fix, a `LEADING_NUMBER` constant stripped with `.replace()`, with the prefix written inside
`SECTION_OPENS` like its neighbours; the behaviour, the cases and the sweep below were unchanged. Its
proposal to share one prefix constant across the four patterns was left out, because it touches
lines outside the fix, and is in section 9.

Reference documents: none. The matcher is benchmark code under `tests/`, which no reference
document describes, and no public contract changed.

Review findings fixed in round 1: S1 (`Findings considered and ruled out` and `Findings verified and
dropped`, which the old pattern closed, opened the findings after the first form of the fix) by the
two qualifiers above, red first at precision 3/4; S2 (the qualifiers and `set aside` had no case) by
five closing headings in `set-aside-words-later.md`, each citing a line no defect holds, so any one
that stops closing fails the case.

  headings close a section, so it needs its own cases.
